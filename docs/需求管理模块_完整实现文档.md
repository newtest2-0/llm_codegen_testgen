## 🧩 1. 修改说明

### 总体功能
在现有的"Professional Code Development Platform"系统中新增了**专业需求管理模块**，包括：

✅ **5个功能框**：
1. 详细需求描述
2. 架构设计
3. 详细设计（含接口+参数+返回值）
4. 需求 → 架构 追溯
5. 需求 → 详细设计 追溯

✅ **4个核心功能**（每个框都有）：
1. **LLMs评阅**：自动使用系统已配置的AI模型生成专业评阅（✨ 复用现有provider系统，无需额外配置）
2. **专家评阅**：用户手动填写评阅意见并保存
3. **下载文档**：导出Markdown格式的文档
4. **上传文档**：导入外部文档到对应章节

✅ **日志记录系统**（预留接口）：
- 使用严格的JSON Schema记录所有LLM评阅操作
- 字段完整，结构规范
- 可扩展到其他模块

### 术语替换
所有"CodeForge"已替换为"Professional Code Development Platform"

### 核心设计理念
**复用现有系统**：
- LLM评阅功能完全复用现有的 `ProviderManager` 和 provider 系统
- 不需要用户额外配置API Key
- 自动使用系统设置中已配置的AI模型

## 📄 2. 新增文件

### 2.1 后端路由：`backend/api/routes/requirements.py`

**文件作用**：需求管理的所有后端API端点

**核心功能**：
- 文档创建和管理
- LLM评阅生成（复用provider系统）
- 专家评阅保存
- 文档上传/下载
- 日志记录（预留接口）

**关键API端点**：
```python
POST   /api/v1/requirements/documents                     # 创建文档
GET    /api/v1/requirements/documents/{doc_id}           # 获取文档
PUT    /api/v1/requirements/documents/{doc_id}/sections  # 更新章节内容
POST   /api/v1/requirements/documents/{doc_id}/llm-review      # LLM评阅（复用provider）
POST   /api/v1/requirements/documents/{doc_id}/expert-review   # 专家评阅
GET    /api/v1/requirements/documents/{doc_id}/download/{type} # 下载文档
POST   /api/v1/requirements/documents/{doc_id}/upload/{type}   # 上传文档
POST   /api/v1/requirements/logs                         # 记录日志（预留）
GET    /api/v1/requirements/logs                         # 获取所有日志
GET    /api/v1/requirements/logs/{log_id}                # 获取指定日志
```

**重要代码片段 - LLM评阅如何复用provider系统**：
```python
# 获取provider管理器（复用现有系统配置）
provider_manager: ProviderManager = req.app.state.provider_manager

# 选择可用的provider
available_providers = provider_manager.get_provider_names()
selected_provider = request.provider if request.provider in available_providers else available_providers[0]

provider = provider_manager.get_provider(selected_provider)

# 调用provider生成评阅（复用现有的generate_code方法）
llm_review = await provider.generate_code(
    requirement=review_prompt,
    language="text",
    extra_directives="输出专业、结构化的评阅报告，使用中文"
)
```

## 🔁 4. 模块之间的数据流说明

### 4.1 LLM评阅流程（核心流程）

```
[前端] 用户点击"LLMs评阅"按钮
   ↓
[前端] 获取章节内容
   ↓
[前端] 发送POST请求到 /api/v1/requirements/documents/{doc_id}/llm-review
   ↓
[后端] requirements.py接收请求
   ↓
[后端] 从 req.app.state 获取 provider_manager（复用系统配置）
   ↓
[后端] 选择可用的provider（优先使用用户指定的，否则选第一个）
   ↓
[后端] 调用 provider.generate_code() 生成评阅
   ↓
[后端] 保存评阅结果到文档
   ↓
[后端] 记录日志（调用 _log_llm_review_event）
   ↓
[后端] 返回评阅结果
   ↓
[前端] 显示评阅内容在蓝色框中
```

**关键点**：
- ✨ **完全复用现有provider系统**
- 不需要额外的API Key配置
- 使用系统设置中已有的AI模型

### 4.2 专家评阅流程

```
[前端] 用户点击"专家评阅"按钮
   ↓
[前端] 显示编辑区（绿色框）
   ↓
[用户] 填写评阅意见
   ↓
[前端] 再次点击按钮保存
   ↓
[前端] 发送POST请求到 /api/v1/requirements/documents/{doc_id}/expert-review
   ↓
[后端] 保存专家评阅到文档
   ↓
[后端] 返回成功消息
   ↓
[前端] 隐藏编辑区，显示通知
```

### 4.3 文档上传/下载流程

**下载流程**：
```
[前端] 点击"下载文档"
   ↓
[前端] 先保存当前内容
   ↓
[前端] 访问 /api/v1/requirements/documents/{doc_id}/download/{section_type}
   ↓
[后端] 生成Markdown格式文档
   ↓
[后端] 返回文件流
   ↓
[前端] 触发浏览器下载
```

**上传流程**：
```
[前端] 点击"上传文档"
   ↓
[前端] 触发文件选择对话框
   ↓
[用户] 选择文件
   ↓
[前端] 使用FormData上传文件
   ↓
[后端] 读取文件内容
   ↓
[后端] 更新章节内容
   ↓
[后端] 返回成功消息
   ↓
[前端] 更新编辑区内容
```

### 4.4 日志记录流程（预留接口）

```
[后端] LLM评阅完成
   ↓
[后端] 调用 _log_llm_review_event()
   ↓
[后端] 构建符合JSON Schema的日志对象
   ↓
[后端] 验证日志结构（_validate_log_schema）
   ↓
[后端] 存储到 _logs_storage（生产环境应存储到数据库）
```

## ❓ 7. 常见问题

### Q1：LLM评阅时提示"没有可用的AI提供者"怎么办？

**A**：需要先在系统设置中配置至少一个AI提供者的API Key：
1. 点击页面右上角的"设置"图标
2. 在"API配置"部分，为任一提供者（如Claude、OpenAI等）输入API Key
3. 点击"保存"按钮
4. 刷新页面后再试

### Q2：如何指定使用特定的LLM进行评阅？

**A**：有两种方式：
1. **前端方式**：修改 `requirements.js` 中的 `generateLLMReview` 函数，添加 `provider` 参数
2. **API方式**：直接调用API时指定provider：
```javascript
fetch('/api/v1/requirements/documents/xxx/llm-review', {
  method: 'POST',
  body: JSON.stringify({
    section_type: 'detailed_requirement',
    content: '...',
    provider: 'claude'  // 指定使用Claude
  })
})
```

### Q3：上传的文档格式有要求吗？

**A**：
- 支持：`.txt`, `.md`, `.doc`, `.docx`
- 编码：UTF-8
- 大小：建议不超过10MB
- 后端会读取文件内容并填充到对应章节

### Q4：下载的文档是什么格式？

**A**：Markdown格式（.md），包含：
- 项目信息（名称、ID、时间）
- 章节内容
- LLM评阅内容
- 专家评阅内容

### Q5：日志记录的JSON Schema必须所有字段都填吗？

**A**：是的。后端有严格的验证逻辑（`_validate_log_schema`），所有必填字段必须存在，但可以为空值：
```json
{
  "id": "xxx",
  "问题锚点": {
```

### Q6：是否需要为LLM评阅功能单独配置API Key？

**A**：**不需要！** 这是本次实现的核心特性：
- LLM评阅功能完全复用系统已有的provider配置
- 使用系统设置中已配置的API Key
- 无需额外配置，开箱即用

### Q7：如何切换到生产数据库？

**A**：当前使用内存存储（`_documents_storage`），生产环境需要：
1. 安装数据库（如PostgreSQL、MySQL）
2. 创建表结构
3. 修改 `requirements.py`，替换内存存储为数据库操作
4. 使用ORM（如SQLAlchemy）管理数据

### Q8：章节内容会自动保存吗？

**A**：会！编辑区失去焦点（blur事件）时会自动保存到后端。也可以手动点击"下载文档"前保存。

### Q9：可以同时打开多个文档吗？

**A**：当前版本使用LocalStorage存储文档ID，只支持一个活跃文档。如需多文档，需要：
1. 修改前端逻辑，支持文档列表
2. 添加文档切换UI
3. 修改后端，支持文档列表查询

### Q10：LLM评阅失败了怎么办？

**A**：检查以下几点：
1. 后端日志：查看具体错误信息
2. API Key：确认provider的API Key正确且有效
3. 网络：确认能访问AI服务商的API
4. 额度：检查API调用额度是否用尽
