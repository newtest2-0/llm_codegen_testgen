# 审阅系统功能说明

## 📋 概述

审阅系统是Professional Code Development Platform的核心功能模块,用于支持专家评测代码生成质量。系统包含5个专业模块,每个模块对应软件开发流程的不同阶段,并支持日志记录功能。

## 🎯 设计理念

采用**方案A - 开发流程对应**,将5个模块映射到软件开发的全流程:

```
项目需求 → 详细需求描述 → 架构设计 → 详细设计 → 需求追溯
```

## 📦 五大核心模块

### 1. 详细需求描述 (Detailed Requirement)
**用途**: 记录问题详情

**包含内容**:
- 触发场景: 问题发生的具体场景和条件
- 错误表现: 
  - 错误日志: 完整的错误信息
  - 功能影响: 对系统功能的影响
- 影响范围: 受影响的模块和功能

**示例**:
```
触发场景: 调用get_user()函数时未初始化数据库连接
错误表现:
  - 错误日志: AttributeError: 'NoneType' object has no attribute 'query'
  - 功能影响: 查询接口返回500错误
影响范围: 用户中心、订单查询功能异常
```

### 2. 架构设计 (Architecture Design)
**用途**: 记录架构层面的设计决策

**包含内容**:
- 技术栈选择: 编程语言、框架、数据库等
- 架构模式: 分层架构、微服务、MVC等
- 模块划分: 核心模块及其职责
- 非功能需求: 性能、安全性、可扩展性考虑

**示例**:
```
技术栈: Python 3.9 + Django 4.2 + PostgreSQL
架构模式: 三层架构(表示层、业务层、数据访问层)
核心模块:
  - 用户认证模块: 处理登录、注册、权限管理
  - 数据查询模块: 封装数据库访问逻辑
  - API接口层: RESTful API设计
性能要求: 支持1000并发用户,响应时间<200ms
```

### 3. 详细设计 (Detailed Design)
**用途**: 记录解决方案和代码实现

**包含内容**:
- 错误原因分析: 问题产生的根本原因
- 解决思路: 整体的解决策略和方法
- 代码对比:
  - 修正前代码
  - 修正后代码
- 关键步骤: 实现的关键点

**示例**:
```python
错误原因分析: db对象未初始化,直接调用query方法
解决思路: 先初始化连接并添加非空校验

修正前代码:
def get_user(user_id):
    result = db.query(User).filter_by(id=user_id).first()

修正后代码:
def get_user(user_id):
    db = connect_db()
    if db is None: 
        raise Exception('连接失败')
    return db.query(User).filter_by(id=user_id).first()

关键步骤:
1. 初始化数据库连接
2. 添加非空校验
3. 异常处理机制
```

### 4. 需求到架构的追溯 (Requirement to Architecture Traceability)
**用途**: 记录问题详情如何映射到架构设计决策

**包含内容**:
- 追溯映射: 问题 → 架构决策
- 影响的架构组件

**示例**:
```
问题: [db-err-001] 数据库连接未初始化导致查询失败
  ↓
架构决策: 
  - 采用连接池管理数据库连接
  - 实现依赖注入模式,统一管理DB实例
  - 添加健康检查机制

影响的架构组件:
  - 数据访问层
  - 配置管理中心
```

### 5. 需求到详细设计的追溯 (Requirement to Design Traceability)
**用途**: 记录问题详情如何映射到具体代码实现

**包含内容**:
- 追溯映射: 问题 → 代码实现
- 测试验证

**示例**:
```python
问题: [db-err-001] AttributeError: 'NoneType' object has no attribute 'query'
  ↓
代码实现:
  函数: get_user(user_id: int) -> User
  修改点:
    1. 添加连接初始化: db = connect_db()
    2. 添加空值检查: if db is None: raise Exception()
    3. 返回值处理: return db.query(...).first()

测试验证:
  - 单元测试: test_get_user_with_invalid_db()
  - 集成测试: test_user_registration_password_hashed()
```

## 🔧 功能按钮说明

每个模块都配备了6个操作按钮:

### 1. 🤖 LLMs评阅
**功能**: 将内容发送给已部署的LLM进行自动评阅和分析

**工作流程**:
1. 用户点击"LLMs评阅"按钮
2. 系统将内容发送到后端API `/api/v1/review/llm`
3. LLM根据字段类型使用专门的提示词进行评阅
4. 返回评阅结果,包括:
   - 整体评价
   - 质量评分(0-100分)
   - 具体的改进建议

**LLM评阅标准**:
- **需求描述**: 关注完整性、清晰度、是否有歧义
- **架构设计**: 关注合理性、技术选型、风险识别
- **详细设计**: 关注正确性、代码质量、最佳实践
- **追溯关系**: 关注完整性、映射合理性、覆盖度

### 2. 👔 专家评阅
**功能**: 允许用户(专家)直接编辑和完善内容

**工作流程**:
1. 点击"专家评阅"打开编辑模态框
2. 专家可以:
   - 直接修改和完善内容
   - 添加评审意见和建议
3. 保存后更新原文本框并记录到日志

### 3. 📥 下载文档
**功能**: 导出当前模块的内容为文本文件

**文件格式**: `.txt` 文件
**文件命名**: `{模块名称}_{时间戳}.txt`

### 4. 📤 上传文档
**功能**: 从本地文件导入内容到模块

**支持格式**: `.txt`, `.md`, `.json`

### 5. 💾 保存记录
**功能**: 保存当前内容到日志历史

**存储方式**: localStorage (浏览器本地存储)

**日志格式**:
```json
{
  "id": "log_1234567890",
  "content": "内容...",
  "fieldName": "详细需求描述",
  "fieldType": "requirement",
  "timestamp": "2024-06-15T15:33:28.000Z",
  "author": "user"
}
```

### 6. 📜 查看日志
**功能**: 查看和管理历史记录

**可执行操作**:
- 查看所有历史记录
- 恢复某条历史记录
- 删除特定记录
- 清空所有日志

## 🔄 映射关系

| 日志字段 | 对应模块 | 说明 |
|---------|---------|------|
| 问题详情 | 详细需求描述 | 记录问题的触发场景、错误表现、影响范围 |
| 架构相关 | 架构设计 | 记录技术栈、架构模式、模块划分 |
| 解决方案 | 详细设计 | 记录代码对比、关键步骤、实现细节 |
| 问题→架构 | 需求到架构追溯 | 记录问题如何驱动架构决策 |
| 问题→代码 | 需求到详细设计追溯 | 记录问题如何映射到具体实现 |

## 🚀 使用流程

### 标准工作流程

1. **记录需求** → 在"详细需求描述"中填写问题详情
2. **设计架构** → 在"架构设计"中规划技术方案
3. **实现代码** → 在"详细设计"中记录代码实现
4. **建立追溯** → 在两个追溯模块中建立映射关系
5. **LLM评阅** → 对每个模块进行AI评阅
6. **专家评阅** → 专家进行人工审核和完善
7. **保存日志** → 将完整的记录保存到日志系统

### 评审工作流程

```
用户输入内容
    ↓
点击LLMs评阅
    ↓
后端调用LLM API
    ↓
返回评阅结果(评价+评分+建议)
    ↓
专家查看并进行人工评审
    ↓
专家修改和完善内容
    ↓
保存最终版本到日志
```

1. **可视化计数器**: 实时显示字符数和日志条数
2. **颜色区分**: 每个模块使用不同配色方案
3. **响应式设计**: 适配不同屏幕尺寸

## 📡 API接口

### POST `/api/v1/review/llm`
LLM评阅接口

**请求体**:
```json
{
  "field_type": "requirement",
  "content": "内容...",
  "field_name": "详细需求描述"
}
```

**响应**:
```json
{
  "success": true,
  "review": "评阅内容...",
  "score": 85,
  "suggestions": ["建议1", "建议2"],
  "field_type": "requirement",
  "field_name": "详细需求描述"
}
```

### POST `/api/v1/review/save`
保存评审记录

### GET `/api/v1/review/history/{field_type}`
获取评审历史

## 🛠️ 技术实现

### 前端
- **框架**: 原生JavaScript + Tailwind CSS
- **存储**: localStorage (浏览器本地存储)
- **文件**: `web/static/js/review_system.js`

### 后端
- **框架**: FastAPI
- **路由**: `backend/api/routes/review.py`
- **模型验证**: Pydantic

### 集成
- 与现有的LLM Provider Manager集成
- 支持多种LLM服务(OpenAI, Claude, DeepSeek等)

## 📝 注意事项

1. **数据存储**: 当前使用localStorage存储,刷新页面数据不会丢失,但清除浏览器缓存会导致数据丢失
2. **LLM可用性**: 需要至少配置一个LLM服务的API密钥
3. **文件上传**: 支持文本文件,会覆盖当前内容
4. **日志管理**: 建议定期导出重要日志,避免数据丢失
